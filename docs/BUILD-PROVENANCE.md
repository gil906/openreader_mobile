# Approved Gradle wrapper bootstrap artifact

The only approved source-tree binary is:

```text
android_app/android/gradle/wrapper/gradle-wrapper.jar
SHA-256: 16caeaf66d57a0d1d2087fef6a97efa62de8da69afa5b908f40db35afc4342da
```

It is the standard Gradle wrapper bootstrap JAR generated by the official
Flutter **3.47.9** SDK, not an app build output, personal document, credential,
or release installer. It is necessary to bootstrap the Android Gradle build.

## Independent public-source verification

The staged JAR's SHA-256 was compared locally with the JAR inside Flutter's
public artifact. The two hashes matched exactly. No private source, runtime
data, credential or signing file was used for this verification.

Flutter 3.47.9 identifies its wrapper artifact in:

- [Flutter wrapper version stamp](https://github.com/flutter/flutter/blob/3.47.9/bin/internal/gradle_wrapper.version)
- [Flutter artifact loader implementation](https://github.com/flutter/flutter/blob/3.47.9/packages/flutter_tools/lib/src/flutter_cache.dart)

Review/pin the distribution checksum separately when maintaining build inputs.

## Strict privacy-guard exception

`tools/check_public_release.py` permits only the exact relative source path
and exact JAR hash above. A changed JAR, a renamed/copied JAR elsewhere, and the
same JAR embedded in an APK are not allowed by this exception. Source ZIPs may
use the project root directly or one enclosing top-level project directory.
The source-archive check retains the original member-path safety checks.

All other document, release-archive, runtime, signing-material, credential,
network-identity, screenshot and secret checks remain unchanged. This is not a
blanket `.jar` allowance. Regenerating a different wrapper requires an explicit
provenance review and a deliberate update to both the pinned hash and these
notes; never change the hash merely to silence a finding.

## APK-only SDK metadata treatment

APK compilation includes public SDK license notices, compiler symbols and
diagnostic strings which are not owner information. The artifact checker has
separate, narrowly scoped handling; none of it permits SDK binaries in source git.

- Seven exact `lib/arm64-v8a/` SDK library paths and
  `kotlin/kotlin.kotlin_builtins` have reviewed SHA-256 metadata pins in
  `APK_SDK_METADATA_SHA256`. They come from the Flutter 3.47.9/locked dependency
  build: Flutter engine, JNI, Android datastore, pdfrx/PDFium and
  sherpa-onnx/ONNX. Relevant locks include `jni` 1.1.1, `pdfrx` 2.11.0,
  `pdfrx_engine` 0.9.0, `sherpa_onnx_android_arm64` 2.0.1 and
  `shared_preferences_android` 2.5.4. These are reviewed candidate byte identities,
  not a claim that every library was independently rebuilt or authenticated
  against a separately downloaded vendor binary.
- These exact bytes may contain public attribution addresses/URLs, shader
  identifiers or lexical-token diagnostic templates. The exception affects only
  low-confidence metadata classification. Changed bytes or paths require fresh
  review and fail closed.
- **Every raw APK entry still receives explicit local-denylist, strong secret
  format, private-IP and private-network-host checks.** Forbidden document/key/
  data paths and document signatures are checked before metadata exceptions.
- App-authored `libapp.so` is not hash-exempt. Its complete bytes remain checked
  for email, host and credential literals. Only 51 exact reviewed Dart SDK
  constructor-symbol fingerprints avoid accidental email classification.
  UTF decoding preserves invalid-byte boundaries rather than joining unrelated
  snapshot strings into invented addresses.
- DEX string tables are parsed individually. Twelve exact reviewed framework
  diagnostic/tag string fingerprints are allowed; app bytecode is not exempt.
- Only the exact APK path
  `META-INF/com/android/build/gradle/app-metadata.properties` may bypass the
  generic runtime-directory rule, and it must contain only the two numeric
  version properties. Source exports do not get this path exception.
- Android resource PNGs may contain structurally validated `npTc`, `npLb` and
  `npOl` nine-patch chunks. This does not allow those chunks in screenshot PNGs,
  arbitrary PNG metadata, or EXIF. Text metadata remains scanned; screenshot
  pixels still require human synthetic-provenance review.

The voice ZIP retains its separate exact hash requirement. No keyword blacklist
classifies ordinary model dictionary/brand words as private documents.
Always rerun artifact scans with the maintainer's explicit private-value inputs,
without logging them, and review final assets rather than an older candidate.

## Audited public installer container

The Docker-save artifact checker accepts only:

```text
openreader_mobile-container-v1.2.0.tar.gz
SHA-256: 637e974cc29c50ab4c859b11c33447928fe8ab9fbbaf6384dcd53d06118ae231
Platform: linux/amd64
Tag: ghcr.io/gil906/openreader_mobile:v1.2.0
```

This exact archive was built from the curated installer dist, HTTP/range tested,
round-trip loaded with Docker, and audited layer by layer. The checker performs
the structural/payload audit again without extracting any tar member:

- Require the exact public tag, platform, archive hash and eight pinned nginx
  base-layer diff IDs. Rehash every decompressed layer against the image config.
- Require the image environment/labels to match the verified public nginx base.
  Scan config/history for explicit private literals, strong secret formats and
  credential assignments, without treating public upstream attribution as owner
  data.
- Scan raw layer bytes, including boundary overlap, for explicit deny literals,
  strong secret formats and private-network information. The exact public base
  has provenance-scoped OS paths/symlinks and crypto parser PEM-header constants;
  those are not user runtime data or owner signing keys. Explicit local deny
  literals still apply to all bytes. Added files get no such key-header waiver.
  Four exact network-shaped fingerprints from public broadcast/link-local
  constants, an upstream configuration example and a nginx JavaScript property
  are also scoped only to those immutable base layers. They do not exempt
  unknown private addresses/hosts or override an explicit owner-value denylist.
- Allow only the five installer web files and nginx configuration as added
  regular files; reject added links, unknown files, traversal, forbidden
  documents/audio and private/runtime additions.
- Recheck embedded APK and source ZIP with the ordinary artifact scanner and
  the model ZIP against its unchanged exact pinned hash. Verify the internal
  manifest has exactly the three corresponding installer checksums, not the
  external container line.

The published external `SHA256SUMS` has four asset lines. The image's internal
manifest has three; the archive is never copied into itself. Native ARM hosts
can build the multi-platform pinned Dockerfile locally, but a newly distributed
archive requires its own platform/provenance audit and deliberate pin update.
